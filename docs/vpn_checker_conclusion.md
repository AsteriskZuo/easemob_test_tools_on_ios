# VPNChecker 工具类：上架判断与技术定性结论

## 前置澄清：两个问题，不要混为一谈

在讨论 VPN 检测时，始终存在两个独立的问题：

| 问题 | 含义 |
|---|---|
| 是否**设置了** VPN | 系统设置里是否存在 VPN 配置（profile），不管它当前有没有连接 |
| 是否**开启了** VPN | 当前是否有 VPN 隧道正在运行、流量正在经过 VPN 通道 |

这两件事的关系是：

- 开启 VPN 的前提是设置了 VPN
- 但设置了 VPN 不代表开启了 VPN
- **真正的关注点是：是否正在开启 VPN**
- 就算能 100% 确认"设置了 VPN"，但无法确认"正在开启 VPN"，那这个信息没有实际意义

后续所有结论都围绕这个区分展开。

---

## 一、技术定性结论

### 1.1 关于"是否设置了 VPN"

| 方案 | 能否判断 |
|---|---|
| `getifaddrs()` 枚举接口 | 不能。VPN 已配置但未连接时，不会产生对应的运行中接口 |
| `NWPathMonitor` | 不能。它观察的是当前网络路径，不读取配置数据库 |
| `NEVPNManager` | 部分能。但只能读到本 App 自己创建/可见的 VPN 配置，不能枚举系统所有 VPN profile |

结论：**在普通 App 权限下，无法系统级确认"是否设置了 VPN"。**

但如前所述，这个问题本身意义有限——知道设置了但不知道是否开启，等于没有有效信息。

### 1.2 关于"是否开启了 VPN"（真正的关注点）

| 方案 | 能否判断 |
|---|---|
| `getifaddrs()` 枚举接口 + 地址特征分析 | 能做到**高置信度识别**，不能做到 100% 确认 |
| `NWPathMonitor` | 能提供辅助信号，不能独立确认 |
| `NEVPNManager` | 只能确认本 App 管理的 VPN 是否连接，不能确认其他来源的 VPN |

具体来说，`getifaddrs()` 方案：

- 当 `utun*` 接口绑定了 `198.18.x.x`、典型私网段、或特征性 ULA IPv6 地址时，可以**大概率判定**有第三方 VPN/代理正在运行
- 但存在假阳性：iCloud Private Relay、Wi-Fi Calling、系统中继等也会创建 `utun*` 接口
- 也存在假阴性：某些 VPN 实现可能不走 `utun*`，或地址特征不典型

**定性结论：能做到"运行态高置信度识别"，不能做到"系统级 100% 确认 VPN 正在开启"。**

### 1.3 一句话总结

> 本方案基于 `getifaddrs()` 枚举网络接口并分析 `utun*` 等虚拟隧道特征，能够在部分典型场景下高置信度识别"当前可能有 VPN/代理隧道在运行"；但它不能系统级、100% 确认设备是否正在使用 VPN，因此不应表述为"系统 VPN 检测器"。

## 二、App Store 上架判断

### 2.1 结论

**可以上架，但有审核风险。风险不在于 `getifaddrs()` 被禁用，而在于审核员可能将其理解为设备指纹或环境探测行为。**

### 2.2 为什么说可以上架

- `getifaddrs()` / `freeifaddrs()` 是标准 BSD API，截至 2026-04 未被 Apple 列为禁用或 Required Reason API
- "网络诊断"是合理的使用理由，Apple 自己的开发者论坛中也有工程师引导开发者使用 `getifaddrs()` 做网络排查

### 2.3 主要风险

| 风险 | 说明 |
|---|---|
| Fingerprinting 嫌疑 | 枚举所有接口名 + IP + flags 的组合理论上可构成设备指纹，审核员可能质疑 |
| 意图质疑 | 如果 App 主功能与网络诊断无关，审核员可能问"为什么需要这个" |
| BSD 接口名不稳定 | Apple 明确说过接口名不是 API，未来可能变化导致功能失效（不影响审核，但影响长期可靠性） |

### 2.4 降低风险的做法

如果用途确实是网络诊断，实现上应保持克制：

1. 仅本地判断，不上传完整接口列表到服务器
2. 不持久化保存原始接口名 / IP / flags
3. 不用于风控封禁、账号画像、广告归因、用户追踪
4. Release 包中去掉详细日志输出（或 `#if DEBUG` 包裹）
5. 对外只产出有限结论，例如：
   - "当前网络环境疑似存在隧道接口，可能影响连接质量"
   - "建议关闭代理/VPN 后重试"
6. 在 App 审核备注中说明用途是"网络诊断 / 连接质量检测"
7. 确保 `PrivacyInfo.xcprivacy` 完整

### 2.5 上架判断一句话

> 集成 `VPNChecker + getifaddrs + freeifaddrs` 用于网络诊断，技术上合规，审核大概率能过；但需要在实现和数据使用上保持克制，避免被误判为设备指纹采集。
